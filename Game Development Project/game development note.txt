Steps:

- Background images & repeating images
I imported background images for the sky, buildings and platform. Instead of stretching the
image, I used wrap mode so it scrolls infinitely. Setting this up was tricky and it took me
a long time to figure out.

I created a 3D object in the 2D scene, set the background image's texture type to Sprite,
sprite mode to Multiple, mesh type to Tight, and wrap mode to Repeat. After creating the
material, choosing the right shader mattered - I picked Lit, then increased the tiling to
more than 1 so the texture repeats.


- Script for background images
I created a MonoBehaviour script, 'BackgroundScroll' (C#), and applied it to all 3 background
images. I wanted each background (sky, buildings, platform) to scroll at a different speed.

meshRenderer.material.mainTextureOffset += new Vector2(scrollSpeed * Time.deltaTime, 0);

(speed x time = distance. scrollSpeed is how fast, Time.deltaTime is how much time just
passed - one tiny frame's worth - and multiplying them tells you how far to move right now.
It keeps the scroll speed the same no matter how fast or slow the computer runs the game.)


- Player Jump 1 - Logic 1
On the player, I added a Rigidbody2D component so gravity physics apply. I created the Player
script. This is where I handle what happens when space is pressed.

I locked the player to a single jump using isGrounded. I used OnCollisionEnter2D to detect
the platform object and set isGrounded to true. So the player can only jump once, but as
soon as they touch the ground again the jump becomes available.


- Player Jump 2 - Add jumping animation
I added jump and land sprites, and in the animator I wired up the flow:
run -> jump -> land -> run.


- Player Jump 3 - Logic 2
I created the parameters in the animator to drive that logic.

- Player Hit and Heal
The idea: when the player hits an enemy they lose HP, and a food item restores HP. The golden
baechu makes the player invincible for a set amount of time. All of this happens when the
player collides with each object.

The player starts with 3 lives, and 'isInvincible' defaults to false.

Inside OnTriggerEnter2D in Player.cs, I created the Hit(), Heal() and StartInvincible()
functions.


------------------------ git 3rd push (version 1.0) --------------------

- Game Manager (UI)
This basically shows the game status (HP) and the interface for the intro, game over, etc.

It needs to be reachable from everywhere, and only one Game Manager should ever exist, so I
made a 'public static GameManager Instance'. I added an Awake method (which runs before
Start) that checks if Instance is null and, if so, sets Instance = this.

I also created an enum GameState with Intro, Playing and Dead.

IntroUI holds the title and start_button, and it's controlled by the Game Manager.

Intro is the default state when the game starts. When the player presses space, it hides the
intro and activates all the spawners (building, enemy, food and gold spawner).


- Player Kill
The player is not killed inside the Player script. I want the Game Manager to know when the
player dies, so it can disable the other states (spawners, etc.), show the lives UI, and
allow restarting the game.


---------

- Heart
First I created the DeadUI and the hearts. I also created the Heart script. Each heart has a
LiveNumber (1, 2, 3) and swaps between its on/off sprite depending on the current lives.


- High score
I added a Canvas with a TMP text. The score is how long the player survives
(Time.time - PlayStartTime). When the player dies, the final score is frozen and saved to
PlayerPrefs if it beats the old high score. On the dead screen it shows the current score,
with the high score on the line underneath.

- difficulty
I want to make the game more difficult if the user has higher score

float speed = 3f + (0.5f * MathF.Floor(CalculateScore() / 10f));
"Every 10 seconds you survive, the game gets 0.5 faster. It starts at 3."

CalculateScore() / 10 → how many 10-second blocks you've lasted
MathF.Floor(...) → whole blocks only (no half-blocks)
× 0.5 → each block adds 0.5 speed
3 + → the starting speed

---------git 4 push-----------
- Intro animation
Title and start button fade in over ~1s ('IntroFade'). Dead screen's restart prompt
now blinks ('Blink').

- Difficulty selection (EASY / NORMAL / HARD)
Picked with Left/Right arrows on the intro screen, stored in a static field so it
survives restart. Each difficulty sets its own start speed (5 / 8 / 12), max speed
(40 / 70 / 100), ramp rate and score multiplier (x1.0 / x1.2 / x1.5). High score is
saved per difficulty.

- Reworked speed/score
Old stepped formula replaced with a smooth ramp: speed = base + elapsed * rampRate,
clamped to max. Score is time-based x the difficulty multiplier. Ramp uses raw time
so the score multiplier doesn't compound into it.

- Items give points
Each food / golden eaten = +1 to score ('BonusPoints', reset each run).

- Character selection (Up/Down arrows)
  - RUNNER (male):   3 hearts, jump 15
  - RUNNER F (female): 2 hearts, jump 20 (higher jump, less health)
A 'Character' class holds name / animator controller / lives / jump force. Run start
applies them and swaps the animator; the preview character on the title screen swaps
live. Heart script hides hearts above the character's max.

- Music Manager
This will play 2 songs. 1st in the background -> 'You Won't Believe What Happened' When game starts -> 'Ready Player Two'

5 sounds made in jsfxr (jump, hit, eat, power-up, game over), played via PlayOneShot.

- Tap support for mobile / touch
Added 'TapInput' - unifies spacebar and mouse click / touch tap. Jump, start and
